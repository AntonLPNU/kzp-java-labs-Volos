# Лабораторні роботи з курсу "Кросплатформні засоби програмування"

## Призначення

Репозиторій містить Java-частину наскрізного навчального продукту для лабораторних робіт 1-5 та окремий Python-пакет для лабораторної роботи №6.

Java-застосунок охоплює лабораторні роботи №1-5: консольну обробку CSV, типізовану модель пасажирських і вантажних рейсів, запити Stream API та типізоване CSV-сховище з round-trip перевіркою. Його поточна версія задається лише в `pom.xml`.

Проєкт розробляється поступово: кожна лабораторна робота додає нову функціональність, але має зберігати працездатність попередніх частин.

## Формат входу

Вхідний файл `data/input.csv` має кодування UTF-8. Один рядок відповідає одній поїздці, поля розділені крапкою з комою.

```text
vehicle;driver;km;fuelLiters;date
```

Приклад:

```text
Львів-Жовква АС-2;Петро Коваль;29.4;6.8;2026-09-10
```

Дані в `data/input.csv` є демонстраційним операційним журналом рейсів. Назви маршрутів узято як бізнес-контекст з напрямків від Львів АС-2, але водії, кілометраж, витрата пального та контрольні хибні рядки є навчальними даними для перевірки програми.

П'ять колонок збережено. Звичайний рядок створює `PassengerTrip`. Для вантажного рейсу поле `vehicle` починається з `CARGO:<load>kg `, де `load` — додатна маса вантажу в кілограмах. Наприклад:

```text
CARGO:1000kg Львів - Жовква доставка;Марія Бойко;29.4;6.8;2026-09-10
```

Окремий `data/lab03-mixed.csv` містить два пасажирські, два вантажні та два навмисно хибні записи. Це навчальна демонстрація, не дані реального перевізника.

## Показники звіту

Програма має обчислити:

- кількість коректних записів;
- сумарний кілометраж;
- середню витрату пального на 100 км;
- найбільшу поїздку.

## Java: лабораторні роботи №1-5

Maven-проєкт містить консольну програму. Вона читає CSV, перевіряє записи, обчислює показники варіанта 7, друкує звіт у консоль і записує його в `out/report.txt`. `Trip` є спільним `sealed abstract` типом із перевіреним незмінним станом; `PassengerTrip` і `CargoTrip` по-різному реалізують `calculatedFuelLiters()`. `TripKind` задає фіксовані категорії. Фабрика `Trip.fromCsv` створює відповідний підтип, а `List<Trip>` і `MileageFuel.plus` обробляють їх без перевірки конкретного типу в обчислювальному циклі.

Для пасажирського рейсу розраховане пальне дорівнює записаному. Для вантажного навчальна оцінка множить записану базову кількість літрів на `1 + loadKg / 10000` (10% на тонну). Цей коефіцієнт є демонстраційним, не нормативом чи перевіреною транспортною моделлю. На старому `data/input.csv` усі рейси пасажирські, тож звіт і показники ЛР №2 залишаються незмінними.

Для рейсу потрібні непорожні `vehicle`, `driver` і `date`, скінченне `km > 0` та скінченне `fuelLiters >= 0`. `NaN` і нескінченність відхиляються. Показники та формат звіту на демонстраційному файлі залишилися такими самими, як у версії 1.0.0.

`TripQueries` реалізує запити варіанта 7: рейси понад 100 км, проєкцію назв транспорту, групову витрату пального на 100 км, `DoubleSummaryStatistics`, топ-N за відстанню/датою та пошук першого рейсу через `Optional`. `Repository<T>` надає типізоване зберігання й пошук. `TripRecord`, `@CsvColumn`, `CsvExporter`, `CsvParser` і `TripCsvStorage` забезпечують анотований UTF-8 CSV, екранування ком, лапок і переносів рядків та відновлення записів. Звіти ЛР №1-5 збережено окремо в `reports/`.

## Python: лабораторна робота №6

ЛР №6 є самостійною Python-програмою в тому самому репозиторії. Java не викликає Python, а Python не змінює Java-код чи його вхідний файл `data/input.csv`. Python-приклад використовує окремий файл `data/lab06-input.csv` з комами між полями.

Пакет `src/kzp_lab06/` розділяє завантаження й перевірку CSV, розрахунки, форматування звіту, помилки та CLI. Потрібен Python 3.11 або новіший. У Windows команди з кореня репозиторію:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m kzp_lab06.cli data\lab06-input.csv out\lab06-report.txt
```

Або після встановлення можна викликати команду `kzp-lab06` з тими самими двома шляхами. Перевірки та збірка wheel:

```powershell
python -m pytest
ruff check .
ruff format --check .
python -m build
```

Докладний звіт ЛР №6 розміщено у [`REPORT.md`](REPORT.md); попередні звіти лежать у [`reports/`](reports/).

Точка входу `Main` лише передає аргументи `ApplicationController`. `CommandLineParser` розбирає параметри, а `TripReportService` формує звіт і виконує експорт CSV. Єдине джерело версії Java-застосунку — `pom.xml`: Maven фільтрує її у ресурс під час збірки, а `--version` читає звідти.

## Запуск

На Windows:

```powershell
.\mvnw.cmd test
.\mvnw.cmd verify
.\mvnw.cmd package
$version = .\mvnw.cmd -q help:evaluate "-Dexpression=project.version" -DforceStdout
$jar = "target\kzp-java-labs-volos-$version.jar"
java -jar $jar
```

Із власними шляхами до вхідного файла та звіту:

```powershell
java -jar $jar --input data\lab03-mixed.csv --output out\report.txt
```

Експорт коректних рейсів із legacy-файла з крапкою з комою до анотованого CSV:

```powershell
java -jar $jar --input data\input.csv --output out\report.txt --csv out\trips.csv
```

Параметр `--csv` необов'язковий. Некоректні вхідні рядки не потрапляють в експорт; програма виводить їхню кількість. `data/lab05-roundtrip.csv` демонструє формат, включно з лапками, комою та quoted multiline значенням.

Версія програми:

```powershell
java -jar $jar --version
```

На macOS та Ubuntu замість `.\mvnw.cmd` використовуйте `./mvnw`. Для Python активуйте `.venv/bin/activate` замість Windows-команди активації.
