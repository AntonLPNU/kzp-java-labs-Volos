## Мета роботи

Створити відтворюваний Java-проєкт і першу версію консольної програми для читання текстових даних, перевірки записів, обчислення показників і формування звіту. Налаштувати Maven, автоматизовані тести, статичний аналіз, пакування JAR і CI для Windows, macOS та Ubuntu.

## Постановка задачі

Створити першу версію консольного Java-продукту для обробки даних про автобусні рейси Львів-Жовква.

Вхідний файл `data/input.csv` містить записи у форматі:

```text
vehicle;driver;km;fuelLiters;date
```

Поля одного запису:

- `vehicle` - назва маршруту або транспортного засобу;
- `driver` - водій;
- `km` - кілометраж поїздки;
- `fuelLiters` - кількість витраченого пального;
- `date` - дата поїздки у форматі `YYYY-MM-DD`.

Програма має прочитати CSV-файл, відкинути хибні рядки з поясненням причини, обчислити показники варіанта 7 і сформувати текстовий звіт.

Дані в `data/input.csv` є демонстраційним операційним журналом рейсів. Назви маршрутів узято як бізнес-контекст з напрямків від Львів АС-2, але водії, кілометраж, витрата пального та контрольні хибні рядки є навчальними даними для перевірки програми.

Показники:

- кількість коректних записів;
- сумарний кілометраж;
- середня витрата пального на 100 км;
- найбільша поїздка.

## Структура програми

Основна логіка розміщена в `src/main/java/ua/lpnu/kzp/Main.java`. Клас містить точку входу `main`, обробляє параметри `--help`, `--version`, `--input` і `--output`, читає вхідний файл у UTF-8, розбирає рядки, перевіряє поля та обчислює підсумкові показники.

Рядок має містити рівно п'ять полів, розділених крапкою з комою. Назва рейсу, водій і дата мають бути непорожніми; кілометраж і витрата пального мають бути числами; кілометраж має бути більшим за нуль, а витрата пального не може бути від'ємною. Для некоректного рядка звіт містить номер рядка та причину відхилення.

Дані зберігаються в `data/input.csv`. Це демонстраційний журнал, а не офіційний розклад чи фактична звітність перевізника: маршрути задають контекст Львівської автостанції №2, решта значень і помилкові записи є навчальними.

Автоматизовані перевірки розміщені в `src/test/java/ua/lpnu/kzp/MainTest.java`. Файл `README.md` описує призначення продукту, формат вхідних даних та команди запуску.

## Інфраструктура

Проєкт використовує Maven Wrapper (`mvnw`, `mvnw.cmd` і `.mvn/wrapper/`), тому Maven запускається однаковими командами на різних операційних системах. У `pom.xml` задано Java 21 і JUnit Jupiter 5.12.2.

Команда `verify` запускає тести та SpotBugs. Команда `package` формує виконуваний JAR із залежностями за допомогою Maven Shade Plugin. Workflow `.github/workflows/java-ci.yml` налаштований на перевірку Windows, macOS та Ubuntu: він виконує `verify`, пакує застосунок, перевіряє `--version` і публікує JAR як артефакт запуску.

## Приклади роботи

Запуск стандартного набору даних у Windows:

```powershell
java -jar target\kzp-java-labs-volos-1.0.0.jar
```

Програма друкує деталі перевірки рядків у консоль і записує такий самий звіт у `out/report.txt`. Для кожного рядка показується статус `valid` або `invalid`; для помилкового запису виводиться причина.

Наприклад, дев'ятий рядок має порожнє поле `vehicle`, тому в звіті він позначений як `invalid` із повідомленням `line 9: vehicle is required`. Так видно не лише факт відхилення, а й місце та причину помилки.

Для `data/input.csv` очікувані підсумки такі:

```text
Rows: 12
Valid rows: 8
Invalid rows: 4
Total distance: 375.10 km
Average fuel consumption: 22.71 l/100 km
Longest trip: Львів 2 - Сокаль 16:20, 78.00 km
```

Вхідний та вихідний файли можна задати параметрами `--input <file>` і `--output <file>`. Довідка та версія доступні через `--help` і `--version`.

## Тестування

У `MainTest` є 14 тестів JUnit для параметрів командного рядка, розбору й валідації полів, обчислення середньої витрати, формування підсумкових показників та запису звіту у файл. Під час попередньої локальної перевірки `mvn verify` завершився успішно: 14 тестів пройшли, SpotBugs не знайшов дефектів. `mvn package` також завершився успішно, а виконуваний JAR вивів версію `kzp-java-labs-volos 1.0.0`.

Workflow CI успішно пройшов на Windows, macOS та Ubuntu після додавання права виконання для `mvnw`. Для кожної ОС зібрано та завантажено JAR-артефакт. [Результат запуску GitHub Actions](https://github.com/AntonLPNU/kzp-java-labs-Volos/actions/runs/36029989962).

Приклад завантажуваного [JAR-артефакта для Ubuntu](https://github.com/AntonLPNU/kzp-java-labs-Volos/actions/runs/36029989962/artifacts/10821350473); у цьому самому запуску доступні артефакти для Windows і macOS. Артефакти GitHub Actions мають обмежений строк зберігання, тому їхня доступність з часом може змінитися.

Версія першої поставки — `1.0.0`: вона задана в `pom.xml`, входить до назви JAR і виводиться через `--version`. Релізний [Git-тег `v1.0.0`](https://github.com/AntonLPNU/kzp-java-labs-Volos/tree/v1.0.0) позначає стан вихідного коду цієї версії. ## Відповіді на контрольні питання

1. `pom.xml` описує Maven-проєкт: його координати й версію, залежності, версію Java та плагіни збірки.
2. `test` компілює й запускає тести; `package` проходить попередні фази та створює JAR; `verify` іде після `package` і в нашому проєкті додатково запускає перевірку SpotBugs.
3. Maven Wrapper фіксує спосіб запуску потрібної версії Maven для всіх учасників і CI, навіть якщо Maven не встановлено глобально.
4. `main(String[] args)` — точка входу: JVM викликає цей метод, передає йому аргументи командного рядка, а далі програма обробляє дані або показує довідку.
5. Примітивний тип, як-от `int` чи `double`, зберігає саме числове значення; `String` є об'єктом із методами для роботи з текстом. Розмір посилання на `String` залежить від JVM, а не від довжини самого тексту.
6. Якщо ділити два `int`, дробова частина відкидається ще до присвоєння результату. Обчислення в `double` дає змогу зберегти дробовий результат середнього.
7. `Integer.parseInt("abc")` кине `NumberFormatException`, бо цей текст не є цілим числом.
8. Мовчазний пропуск помилкового рядка приховує втрату даних. Номер рядка й причина в звіті дають змогу виправити джерело та перевірити підсумки.
9. `split(";", -1)` збереже порожнє поле після останньої `;`. Без від'ємного параметра кінцеві порожні поля відкидаються, і кількість полів можна визначити неправильно.
10. `Path.of("data", "input.csv")` складає шлях засобами Java для поточної ОС; рядок із `\\` прив'язаний до стилю шляхів Windows.
11. Явне `UTF-8` гарантує однакове читання й запис українського тексту незалежно від стандартного кодування системи.
12. `%n` у форматованому виводі означає системний роздільник рядків, а `\n` — конкретний символ нового рядка.
13. У варіанті 7 потрібно мати рівно п'ять полів; `vehicle`, `driver` і `date` не можуть бути порожніми; `km` і `fuelLiters` мають бути числами, причому `km > 0`, а `fuelLiters >= 0`.
14. Для середньої витрати варто перевірити різні довжини поїздок, нульове пальне та заборону нульового кілометражу. Наприклад, 10 л на 50 км і 30 л на 300 км разом дають `40 / 350 * 100 = 11.43` л/100 км, а не просте середнє 20 і 10.
15. Статичний аналізатор досліджує код без запуску програми й шукає типові потенційні дефекти. У нас цю перевірку виконує SpotBugs під час `verify`.
16. GitHub Actions запускає збірку й перевірки після змін у репозиторії. Наш workflow перевіряє Java-проєкт на Ubuntu, Windows і macOS та зберігає JAR як артефакт.
17. Issue про дефект має містити очікувану й фактичну поведінку, кроки відтворення, вхідні дані, середовище та, за наявності, повідомлення про помилку.
18. У звіті треба чесно вказати інструмент ШІ, його ролі, приклади запитів, прийняті й відхилені поради, виправлення та власний внесок у перевірку результату.
19. DevOps відповідає за відтворювану збірку, CI й артефакти; Валідатор перевіряє вхідні дані, негативні випадки та коректність відхилення хибних записів.
20. Найбільше уваги в моєму коді потребує `line.split(";", -1)`: параметр `-1` легко пропустити, але саме він зберігає порожнє останнє поле, потрібне для правильної перевірки CSV-рядка.
