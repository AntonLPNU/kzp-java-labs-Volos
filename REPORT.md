## 3. Варіант і вхідні дані

Варіант 7 моделює рейси автопарку. CSV-файл `data/lab06-input.csv` має UTF-8 кодування, роздільник-коми та точний заголовок:

```text
vehicle,driver,date,kilometers,fuel_liters
```

На відміну від Java-файла `data/input.csv`, у якому використовується крапка з комою, файл ЛР6 має окрему назву й не змінює формат попередніх лабораторних. Кома всередині назви маршруту `Доставка, північ` захищена стандартним CSV-цитуванням.

Порожній файл без заголовка відхиляється як некоректний. CSV лише із правильним заголовком є коректним і означає нуль записів. Обов'язкові текстові значення не можуть бути порожніми; дата має формат ISO `YYYY-MM-DD`; кілометраж має бути скінченним числом більше нуля, пальне — скінченним невід'ємним числом.

## 4. Структура Python-пакета

- `src/kzp_lab06/loader.py`: читання через `csv.DictReader`, перевірка заголовка та рядків, перетворення чисел і дат.
- `src/kzp_lab06/analysis.py`: фільтрація, множина водіїв, групування кілометражу та підсумки.
- `src/kzp_lab06/reporting.py`: стабільне форматування й запис UTF-8 звіту.
- `src/kzp_lab06/errors.py`: помилка предметної області `DataError`.
- `src/kzp_lab06/cli.py`: аргументи командного рядка та коди завершення.
- `tests/test_lab06.py`: автоматизовані перевірки.

## 5. Завантаження та валідація CSV

Файл відкривається через `Path.open(encoding=\"utf-8\", newline=\"\")`, як рекомендує модуль `csv`. `DictReader` зіставляє назви колонок із рядковими значеннями й коректно обробляє коми всередині лапок. Заголовок має збігатися з визначеним списком колонок; зайві або відсутні поля відхиляються.

Кожен прийнятий рядок перетворюється на словник із рядками `vehicle` і `driver`, об'єктом `datetime.date`, а також числовими `kilometers` і `fuel_liters`. Помилка значення містить номер рядка. Початкові помилки перетворення зберігаються як `__cause__`; помилки читання та синтаксису CSV загортаються в `DataError`.

## 6. Колекції та вирази-генератори

Функція `long_trips` повертає список рейсів із кілометражем строго понад 100 км. `drivers` формує множину унікальних імен водіїв. `kilometers_by_vehicle` повертає словник суми кілометрів за кожним транспортним засобом, а ключі сортуються для відтворюваного звіту.

У реалізації використано list comprehension для відбору рейсів, set comprehension для множини водіїв і dict comprehension для групового результату. Суми обчислюються генераторними виразами.

## 7. Функції та аргументи

`summarize` демонструє позиційні змінні аргументи `*metrics`, іменований параметр за замовчуванням `minimum_km=0.0` та довільні іменовані аргументи `**labels`. Функція перевіряє допустимі метрики, відбирає записи за порогом і повертає кількість та запитані суми з можливістю задати для них альтернативні назви.

`fuel_per_100_km` обчислює загальне споживання за формулою `паливо / відстань * 100`. Для порожнього набору повертається 0, щоб уникнути ділення на нуль.

## 8. Формування звіту

Звіт містить кількість рейсів, кількість рейсів понад 100 км, загальну відстань, сумарне пальне, середню витрату на 100 км, унікальних водіїв і кілометраж за кожним транспортним засобом. Форматування має стабільний порядок, відстані та пальне показуються з двома десятковими знаками. Запис створює батьківський каталог за потреби та використовує UTF-8 і `\\n`.

## 9. Командний рядок

Інтерфейс приймає два позиційні аргументи: шлях до вхідного CSV і шлях до текстового звіту. У разі успіху повертає код 0; некоректні дані або помилки файлової системи дають повідомлення в stderr і код 1. Помилку розбору аргументів обробляє стандартний `argparse`.

Приклад запуску в Windows:

```powershell
python -m venv .venv
.\\.venv\\Scripts\\Activate.ps1
python -m pip install -e \".[dev]\"
python -m kzp_lab06.cli data\\lab06-input.csv out\\lab06-report.txt
```

## 10. Налаштування проєкту та CI

`pyproject.toml` визначає метадані пакета, мінімальну версію Python, точку входу `kzp-lab06` і додаткові засоби розробки: pytest, Ruff та build. Зібраний wheel можна встановити окремо від Maven-проєкту.

`.github/workflows/python-ci.yml` запускає перевірки на Ubuntu, Windows і macOS із Python 3.12: встановлення проєкту, pytest, Ruff lint, перевірку форматування, збірку wheel і завантаження артефакту. Java CI залишається окремим workflow.
